# 浏览器直连采用双 WebRTC DataChannel

浏览器直连使用无序、不重传的画面数据通道传送采集卡原生 MJPEG，并使用可靠、有序的控制数据通道传送输入、状态和错误。每张不超过 16 MiB 的 MJPEG 按不超过 16 KiB 的应用层消息分片，分片头携带帧编号、分片序号、分片总数和整帧长度；浏览器最多同时重组最近两帧，允许旧帧尾片晚于新帧首片到达，较新帧完整或第三帧开始后才淘汰更旧的未完成帧。最终缺片的整帧会被舍弃且不请求重传；空帧或超限帧通过可靠控制通道报告 `VIDEO_FRAME_INVALID`。这样既避开不同 WebRTC 实现的单消息长度限制，也不会让旧画面阻塞实时控制。标准 WebRTC 视频轨道通常要求 H.264、VP8 或 AV1，而一级支持硬件无法把 1080p30 MJPEG 实时软件转码为这些格式；双 DataChannel 已在香橙派 One 上验证跨公网传输，同时允许画面拥塞时舍弃帧而不牺牲控制消息可靠性。
