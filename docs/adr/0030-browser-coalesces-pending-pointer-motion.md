# 浏览器会话合并尚未执行的指针移动

浏览器控制通道保持可靠、有序，但可靠传输不等于必须把每个过时的鼠标采样都写入 USB。部分 UEFI 固件只以约 `110 ms` 的周期消费 HID 报告；如果服务端同步执行每个浏览器 `mousemove`，旧轨迹会形成数秒队列，并阻挡其后的键盘和按钮操作。

每个浏览器连接因此使用独立输入执行器。所有消息先完成语义校验，再决定是否合并。已经开始的 HID 操作不会因浏览器断线而取消；尚未执行且相邻的绝对纯移动由最新坐标替换，相对纯移动在合法范围内累计。键盘状态、按钮按下或释放、滚轮和 `release_all` 构成顺序屏障，移动不得跨过它们合并。可靠输入达到内部容量时对连接读取施加反压，不拒绝已经接收的顺序屏障。`release_all` 清除尚未执行的输入；连接关闭等待当前操作结束后再执行最终释放，避免迟到的输入重新留下按下状态。

Linux HID 文件以非阻塞方式打开，并最多等待两秒让 USB 主机取走上一份报告。正常固件轮询仍保持同步顺序；USB 主机完全停止消费时返回明确写入错误，使连接清理不会永久等待。

该策略同时用于 WebRTC 直连和 WebSocket 转发，只改变浏览器高频指针状态的排队方式，不改变 MCP 原子输入操作的同步语义。

## 实机验证

一级支持的香橙派 One 使用 `musb-hdrc` USB Device 控制器，连接 ASUS TUF B450M-PRO GAMING BIOS 1820。固件下三个 HID 端点的连续报告完成周期实测约为 `110 ms`。经 WebSocket 一次性发送三十个绝对坐标后紧接 Caps Lock，使用键盘 LED 输出报告作为非图形化回执，优化后的端到端回执约为 `29.6 ms`；测试末尾再次切换并确认 LED 状态从 `03` 恢复为 `01`。Linux ARMv7 还以真实非阻塞满管道验证了持续不可写超时、`EINTR` 重试和恢复可写三条底层路径。
