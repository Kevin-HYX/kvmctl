# 浏览器交互通道 v0.2

## 范围

浏览器控制会话长期支持两种互斥的交互通道：默认的 WebRTC 直连通道，以及经既有 HTTPS、WebSocket 和转发基础设施承载的转发通道。浏览器入口、会话 Cookie、五秒控制空闲释放、六十秒重连窗口和全局单会话约束保持不变。

## 直连通道

- 浏览器通过受会话 Cookie 和严格 Origin 保护的 `POST /control/webrtc/offer` 提交完整 SDP offer，控制设备返回完整 SDP answer。
- 默认使用 `stun:stun.cloudflare.com:3478` 和 `stun:stun.l.google.com:19302`；配置可覆盖或禁用默认 STUN。
- 首版不配置 TURN。ICE 无法直连时必须返回稳定失败状态，不能自动切换通道。
- `frames` DataChannel 必须无序且不重传。每张不超过 16 MiB 的 MJPEG 使用带协议标识、32 位帧编号、分片序号、分片总数和整帧长度的 16 字节头部拆为消息总长不超过 16 KiB 的分片。浏览器最多同时重组最近两帧，允许旧帧尾片晚于新帧首片到达；较新帧完整或第三帧开始后才淘汰更旧的未完成帧。最终缺失、迟到或重复的分片不得触发重传。发送端只在 SCTP 发送缓冲为空时提交新帧，拥塞时继续采集但舍弃帧；采集源返回空帧或超限帧时通过可靠控制通道报告 `VIDEO_FRAME_INVALID` 并重新打开画面流，不能因此关闭仍然健康的控制通道。
- `control` DataChannel 必须可靠且有序，复用 WebSocket 已有的键盘、指针、释放和心跳 JSON 消息，并承载状态与稳定错误消息。
- 服务端必须在每个浏览器连接内异步执行 HID 输入。输入在参与合并前必须完成语义校验。尚未执行且相邻的纯绝对移动只保留最新坐标；尚未执行且相邻的纯相对移动合并为等量总位移。键盘状态、鼠标按钮变化、滚轮和 `release_all` 是顺序屏障，不得被移动合并跨越；内部容量不足时必须对连接读取施加反压，不能丢弃顺序屏障。断线必须丢弃尚未执行的移动、等待当前写入完成或明确失败，然后释放全部 HID 状态。
- 两条 DataChannel 同时打开后直连才算成功；任一通道失败或 PeerConnection 断开都必须释放全部 HID 状态并结束该次连接。
- 首次尝试十秒未成功即显示失败；浏览器在会话剩余的六十秒重连窗口内只自动重试当前选择的直连通道。

## 通道选择

- 默认选择直连，转发是永久受支持能力。
- 只有浏览器操作者可以在同一会话中双向改变选择；MCP 和服务端不得自动改变。
- 改变选择前必须发送并执行 `release_all`，关闭旧通道，再建立新通道。
- 选择失败停留在明确错误状态，不自动返回另一种通道。
- UI 的最终呈现不属于本规格；正式接口只需提供可操作的基础选择控件。

## 状态与敏感信息

- `browser_session_status` 增加当前选择、通道状态、最近稳定错误码和重连截止时间。
- MCP 不接收浏览器自报的 FPS、码率或 RTT。
- 常规页面可显示候选类型、RTT、FPS 和码率，但不显示地址或端口。
- SDP、ICE 候选、具体公网地址和端口不得进入常规服务日志或 MCP 输出；只有显式临时诊断允许输出。

## 验收缝

1. 无有效浏览器会话或 Origin 不匹配的 WebRTC offer 与现有私有资源一样返回 `404`。
2. 有效 offer 建立无序不重传的画面通道和可靠有序的控制通道；两者同时打开前状态不得为已连接。
3. 画面通道把超过协商单消息上限的真实 MJPEG 分片发送，浏览器能乱序重组完整帧，并在新帧首片早于旧帧尾片到达时保留两帧并行重组；拥塞时发送缓冲保持有界，控制通道输入进入现有控制权仲裁与 HID 操作路径。
4. 直连断开或通道切换释放全部 HID 状态，并允许原 Cookie 在六十秒内建立选定通道。
5. 现有 WebSocket 转发行为及最新帧确认协议保持通过。
6. ARMv7 产物可在香橙派 One 建立公网 `srflx/udp` 候选对并完成画面、控制往返。
7. 在控制器每次指针状态写入耗时 `110 ms` 的测试中，连续三十次绝对移动只执行至多一个在途状态和一个最新待执行状态；相对移动保持总位移，按钮按下与释放保持原顺序，随后键盘状态不得排在三十份陈旧移动之后。
